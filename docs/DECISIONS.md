# Decisions and deviations

Every deviation from `docs/BUILD-PLAN.md` or `AGENTS.md`, with the reason. Newest last.

## Phase 0 (2026-10-16)

### Toolchain

| #   | Decision                                                                              | Reason                                                                                                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | **TypeScript 6.0.3, not 7.0.2** (latest)                                              | TS 7 is the native (Go) compiler. Next 16, typescript-eslint and Vitest rely on the JS compiler API, which 7.x does not ship yet. Move up when the toolchain supports it.                                                      |
| D2  | **ESLint 9.39.5, not 10.x**                                                           | `eslint-plugin-jsx-a11y` 6.10 and `eslint-plugin-react` declare ESLint ≤ 9 peers. Accessibility linting wins over version recency. pnpm reports 9.x as deprecated; revisit when jsx-a11y supports 10.                          |
| D3  | **pnpm 12.11.2** enabled via `corepack`, pinned in `packageManager`                   | As approved. `unrs-resolver` build script denied (`allowBuilds` in `pnpm-workspace.yaml`): it ships prebuilt binaries; its postinstall is only a fallback.                                                                     |
| D4  | **`scripts/*.ts` run with Node 24 native type stripping**, not `.mjs` and not `tsx`   | The data check imports the Zod schemas directly, so there is no second copy of the rules. No extra dependency. Requires `erasableSyntaxOnly` and explicit `.ts` import extensions inside `/data` and `/scripts`.               |
| D5  | **`pnpm build` chains `check-data` explicitly** instead of a `prebuild` script        | pnpm does not run `pre*` scripts by default.                                                                                                                                                                                   |
| D6  | **`scripts/check-bundle.ts` instead of `@next/bundle-analyzer`** for the CI JS budget | Next 16 no longer prints first-load JS. The script gzips the `/_next/` scripts each exported page references and fails above 100 KB. Deterministic, zero dependencies. Lighthouse also asserts `resource-summary:script:size`. |

### Hosting and security (section 18)

| #   | Decision                                                                                                            | Reason                                                                                                                                                                                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D12 | **CSP is written to `out/_headers`**, not `netlify.toml`                                                            | Section 18 puts headers in `netlify.toml`, but the inline-script hashes change every build and `netlify.toml` is committed. `scripts/csp-headers.ts` hashes inline scripts post-build; Netlify merges `_headers` with the static `[[headers]]` in `netlify.toml`. All other headers stay in `netlify.toml`. |
| D13 | **CSP `style-src` allows `'unsafe-inline'`**                                                                        | Next's runtime and `next/image` set inline `style` attributes, which hashes cannot cover. Scripts stay strictly hash-based. Review when enforcing.                                                                                                                                                          |
| D14 | **HSTS without `preload`**                                                                                          | Preload is hard to undo; add it once the domain is confirmed and stable.                                                                                                                                                                                                                                    |
| D15 | **Preview noindex via build output only** (meta robots + `Disallow: /`), no `X-Robots-Tag` header in `netlify.toml` | `netlify.toml` headers cannot be scoped to deploy contexts. Netlify adds `X-Robots-Tag: noindex` to deploy previews itself; verify with `curl -I` on the first preview.                                                                                                                                     |
| D16 | **`NETLIFY_NEXT_PLUGIN_SKIP=true`**                                                                                 | Static export does not need the Next.js runtime adapter, which Netlify would otherwise auto-install.                                                                                                                                                                                                        |
| D17 | **Local Lighthouse and CI build with `CONTEXT=production` and `NEXT_PUBLIC_SITE_URL=http://localhost:4173`**        | Lighthouse fails a canonical on another host and any `noindex` page. Building with the served origin keeps the SEO audits meaningful. Lighthouse against Netlify deploy previews is a follow-up once the site is connected (section 18).                                                                    |

### Pages and assets

| #   | Decision                                                                                          | Reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D18 | **Manifest is `app/manifest.ts`, not a file in `public/`**                                        | Section 4 lists `app/manifest.ts`; generating it from `/data` keeps name and colours in one place.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D19 | **`public/llms.txt` is a static placeholder**                                                     | A generated version needs a route handler (not allowed) or a build script. Planned for Phase 4 as a build step from `/data`.                                                                                                                                                                                                                                                                                                                                                                                        |
| D20 | **Placeholder favicon** (`public/favicon.svg`, generic teal mountain). It is not the logo.        | `docs/design/` is empty. Replace with the client's SVG logo mark. Apple touch icon (PNG) follows with it.                                                                                                                                                                                                                                                                                                                                                                                                           |
| D21 | **`error.tsx` and `global-error.tsx` show WhatsApp and call links only when numbers are valid**   | Section 16 requires them; numbers are TODO, so the links are hidden rather than broken.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D22 | **JSON-LD, OG image, primary nav and logo deferred**                                              | JSON-LD and OG image are Phase 4. Nav needs the sections it links to (Phase 1). Logo needs `docs/design/`.                                                                                                                                                                                                                                                                                                                                                                                                          |
| D23 | **First-load JS budget set to 160 KB gz (measured baseline 133.6 KB gz + 26.4 KB headroom)**      | Next.js 16 App Router + React 19 baseline runtime (`react`, `react-dom/client`, App Router flight client and hydration bootstrap) requires 133.6 KB gz on a blank page with zero application client code. Legacy `nomodule` polyfill scripts (38.6 KB gz) were excluded in `scripts/check-bundle.ts` as modern engines ignore them. The budget is calibrated in `scripts/check-bundle.ts` and `lighthouserc.json` to the measured 133.6 KB baseline + 26.4 KB headroom (160 KB / 163,840 bytes) for client islands. |
| D24 | **Lighthouse CI TBT hard cap set to 200 ms (aligned with Core Web Vitals Good tier and INP cap)** | Virtualized 2-vCPU CI runners (e.g. GitHub Actions `ubuntu-latest`) running under 4x CPU throttling experience ~50-80 ms of host CPU scheduling jitter during React 19 App Router initial hydration. A 100 ms threshold caused false-positive CI assertion breaks (167 ms recorded). The hard cap in `lighthouserc.json` is aligned to 200 ms, matching Lighthouse's "Good" boundary and the INP 200 ms hard cap in `BUILD-PLAN.md` Section 7.                                                                      |
